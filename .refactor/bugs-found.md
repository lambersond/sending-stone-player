## [U2] Sheet parts

- `src/components/character-sheet/use-picker.tsx:701` — the tick list's lead says "Up to N." with N uncapped (`leadFor(area, takes)`), while ticking stops at `Math.min(takes, MAX_USE_TARGETS)` (20, line 695) — the words promise more targets than can be ticked — a use or area attack whose `targets.count` (+ `perLevel` upcast) exceeds 20, in a combat of 21+ combatants: the lead reads "Up to 24." and the 21st tick is disabled; a count of null ("any number") ticks at most 20 with no limit said — [U2] (seen in code, low).
- `src/components/character-sheet/actions-tab.tsx:730` — in the table layout an activity's uses (and its Recharge chip) are named `actionTitle(action)` ("Item (Activity)"), where the list layout's activity row (`action-entry.tsx:866-877`) and the table's item row (`actions-tab.tsx:595`) name them `usesName(action, uses)` (the item's name unless the counter is the activity's own) — the same uses get different accessible names by layout — an item whose folded activity (not a cast/forward one) carries the item's own counter, Actions tab at Table layout vs List layout: the uses button's name differs — [U2] (to confirm: depends on whether the module ever sends an activity `uses` whose counter is the item's).

- [V2] `src/components/character-sheet/sheet-tiles.tsx:445`, `src/components/game-table/chat-log.tsx:788`, `src/components/avatar/avatar.tsx:40` — initials take the first UTF-16 code unit (`word[0]`, `charAt(0)`), so a name whose word starts with an astral character (an emoji, many CJK extension letters) gives a lone surrogate, drawn as a replacement box; `src/utils/campaign-order.ts:105` (`[...word][0]`) gets it right, so the same name shows differently on the campaigns page and on the sheet or chat — why: a broken glyph in an avatar — reproduce: `node -e "console.log(JSON.stringify('🐉 Ember'.split(/\s+/).map(w=>w[0].toUpperCase()).join('')))"` prints `"\ud83dE"`; name a Foundry actor "🐉 Ember" and open its sheet's companion tiles or the chat log.
- [V2] (to confirm) `src/hooks/use-companion-view.ts:84-93` — the companion pane's poll never backs off: a failed read (network error, 5xx) is retried every POLL_INTERVAL (3 s) for as long as the pane is shown, and nothing says it is reconnecting, while the table, party, notes and cookbook polls double their wait up to 30 s / 120 s and show "reconnecting" — why: during an outage each open companion pane keeps a 3 s request rate and the pane silently shows stale data — reproduce: open a companion pane, stop the server or make `/api/characters/<id>/companions/<key>/table` answer 500; the network tab shows a request every 3 s and no reconnecting state.
- [V2] (to confirm) `src/hooks/use-notes.ts:337-357` — a 401 (signed out in another tab, session lapsed) is counted as a failure: the journal keeps polling with backoff and, with no view yet, shows 'failed', where the table and party polls refresh the page (which sends to sign-in) — why: on a page whose other poller does not refresh first, the journal says it failed rather than asking to sign in — reproduce: open a party page's journal, sign out in another tab; the party poll's 401 refreshes the page, but a journal-only mount (biography tab before the table poll's next tick) shows the failed state for up to 3 s.

## [S] Server

- [S] `src/db/campaigns.ts:437` (via `src/app/api/events/route.ts:127`) — a `bridge.ping` (connection test, `record: false`) whose typed title matches a campaign waiting for Foundry and whose secret is right **binds** that campaign: `bind()` writes `foundryId` (and, where the module's campaign was followed before it was set up, merges the set-up into it in a transaction) — why: PROTOCOL.md:1513 says of `bridge.ping` "Store nothing", and the route's own comment says nothing is recorded of a test whose title and secret are as typed, perhaps not saved; a Test from another campaign of the same game, typed with this campaign's title and secret, binds this campaign to the wrong module campaign id, after which the real campaign's events find no candidate (`foundryId: null` is required) and are refused 404 `notSetUp` — reproduce: set up campaign "A" with secret s (unbound); POST /api/events a `bridge.ping` with `campaign: {id: 'm2', title: 'A'}` and `Authorization: Bearer s` → 204 and the row now has `foundryId = 'm2'`; then the hello of the real campaign `{id: 'm1', title: 'A'}` → 404 (seen in code; the db test "records nothing for a connection test", campaigns.test.ts:936, covers only refusals).
- [S] `src/lib/seat-routes.ts:126`, `src/lib/notes-routes.ts:183` — a roll's and a note's body is read whole (`request.text()`) before its size is checked, with no check of a declared `Content-Length` first, unlike `/api/events`, `/api/bridge/commands` and the cookbook's dishes, which refuse a declared oversize before reading — why: a signed-in user can make the server buffer an arbitrarily large body before the 413 (memory), and the five body readers disagree on it — reproduce: POST /api/characters/<id>/rolls signed in, `Content-Type: application/json`, a 100 MB body: it is read in full, then answered 413 (seen in code, low: hardening).
- [S] (to confirm) `src/app/api/characters/[id]/texts/[hash]/route.ts:18,21,23`, `src/app/api/campaigns/[id]/characters/[actor]/texts/[hash]/route.ts:15` — the two sheet-text routes answer 401 (and the player's route its two 404s) with no `Cache-Control` at all, where every other seat route, the companions' text routes included, answers 401/404 `no-store` — why: an auth-dependent answer without a cache directive, inconsistent with its siblings (likely harmless: no validators, so no heuristic caching) — reproduce: GET /api/characters/x/texts/zz signed out: no Cache-Control header; GET /api/characters/x/companions/k/texts/zz signed out: `no-store`.
- [S] (to confirm) `src/lib/app-origin.ts:9` — `x-forwarded-host` is taken whole while `x-forwarded-proto` is split at its first comma, so behind chained proxies (`X-Forwarded-Host: a.example, b.example`) the origin is `https://a.example, b.example`, and the campaigns page shows a wrong listener address and invite link — reproduce: GET /campaigns with `X-Forwarded-Host: a.example, b.example` (Vercel sends one value, so likely latent).
- [S] (low) `src/db/roll-requests.ts:748,773`, `src/db/cookbook.ts:223` — the throttles `noted`, `tablesNoted` and `pruned` are process-wide Maps keyed by campaign or character id that are never pruned: one entry per campaign or character ever seen, for the life of the server — why: unbounded growth in a long-running server (small per entry) — reproduce: poll the tables of N characters; `tablesNoted.size` is N and never shrinks (seen in code).
